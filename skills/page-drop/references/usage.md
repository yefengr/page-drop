# PageDrop 使用参考

本文件补充安装、参数和维护验收，不另设发布流程。授权、公开边界和 pending 决策以 [主技能](../SKILL.md) 为准。

## 技能包与 CLI 入口

完整复制技能目录即可携带 CLI 和本参考资料；运行只需要 Python 3 标准库，支持 macOS/Linux，不需要 Git 仓库、开发虚拟环境或全局 `publish`。服务仍需另行部署，联网命令还需配置服务地址和凭据。脚本内的开发契约注释可能指向仓库技术文档，仅作维护说明；独立分发以本参考和 `SKILL.md` 为准，运行时不读取该文档。

从实际加载的 `SKILL.md` 所在路径确定当前技能目录，不假设 harness 专属环境变量。以下 `<当前技能目录>` 是说明用占位符：执行前必须替换为已确认的绝对路径，路径带空格时保留引号。例如：

```bash
python3 "<当前技能目录>/scripts/publish" --help
```

缺少 Python 或技能内脚本时说明缺口并停止，不自动联网下载、安装工具或修改 PATH。用户可以另行授权将技能内脚本或开发仓库的兼容入口链接到 PATH，作为可选便利；先确认目标不存在，不覆盖已有文件，移动原目录后须重新核对链接。

## 配置与凭据

- 非空 `PAGE_DROP_CONFIG_DIR` 可指定配置目录，必须是绝对路径，不展开 `~` 或环境变量；指定后只使用该目录的 `config.json` 和默认 `token`，目录或文件缺失、Token 为空、配置损坏时都不回退到新旧默认目录，也不自动创建目录。显式 `token_file` 仍按原语义使用，包括相对路径以调用者工作目录为基准。不要为绕过缺失配置或 pending 冲突擅自切换配置目录。
- 未设置 `PAGE_DROP_CONFIG_DIR` 或其值为空字符串时，配置文件优先使用 `~/.config/page-drop/config.json`；不存在时兼容旧的 `~/.config/edge-publish/config.json`。两份配置均不存在时，依次选择新、旧目录中已存在的 `token`；均无时使用新目录默认值。字段包括 `base_url`、`token_file`、`timeout`；不合并新旧配置，也不硬编码服务域名。
- 配置和 Token 保留在用户私有位置；覆盖配置目录不会改变锁、临时归档、pending 和 history 的位置，它们仍使用 `~/.local/state/publish/`，不写入技能目录。容器中可将配置目录指向已有的私有持久目录，但应另行确认恢复状态是否持久化；目录变量只放路径，不放 Token。
- 凭据优先级：非空 `PAGE_DROP_TOKEN` → 非空旧 `EDGE_PUBLISH_TOKEN` → 所选配置指定的 `token_file` → 所选配置目录中的 `token`。仅检查存在性、可读性和有效配置，不输出 Token 或整份环境变量；检查脚本仅返回布尔结果或脱敏错误。
- 配置与 Token 文件权限按项目约定为 `0600`；需要修正权限时先取得对应授权。凭据由用户在本地配置，不通过对话传递。
- 需要联网的命令必须显式配置自部署服务的 `base_url`，没有默认服务器；线上地址必须为 HTTPS。dry-run 与 discard-pending 不需要地址。存在 pending 时，不为恢复上传擅自改 base_url；CLI 会拒绝向不同目标发送原归档。
- CLI 遵循代理环境变量与 `NO_PROXY`，目前代理地址仅支持 `http://` 协议。连接异常先按 CLI 报错核对配置，不输出带代理凭据的 URL，不擅自切换服务或网络设置。
- dry-run 不请求服务、不加载 Token、不新增 pending，但会使用本地锁和临时打包；已有 pending 仍会阻止它。discard-pending 同样不需要 Token，但会删除本地恢复材料，不是只读操作。

## 参数与命令

- 用户未明确指定有效期时，技能为预检和发布默认使用 `3d`；用户明确指定时按其要求，模糊或冲突时先询问。CLI 本身仍要求显式提供 `--ttl`。TTL 使用正整数加 `m`、`h`、`d`，总时长为 10 分钟至 30 天，例如 `10m`、`2h`、`3d`；`1.5h`、`1h30m` 不合法。服务端从提交成功时起计时。
- `--title` 为可选标题，`--label` 为可选追溯标签，均默认空；label 最多 64 个字符，不含控制字符。
- 目录带空格时使用 shell 引号。目录名若与管理命令重名，例如 `retry`，使用 `./retry` 或绝对路径。
- 支持 `--json` 的命令优先使用它，仍须检查 stderr。`url`、`rm`、`discard-pending` 不支持该参数。
- 下列命令是独立示例，不是依次运行的脚本；发布、retry、删除与丢弃都必须分别满足主技能中的授权条件。

仅本地预检：

```bash
python3 "<当前技能目录>/scripts/publish" ./dist --ttl 3d --dry-run --json
```

正式发布：

```bash
python3 "<当前技能目录>/scripts/publish" ./dist --ttl 3d --title "评审稿" --label "评审机" --json
```

查询与取回链接：

```bash
python3 "<当前技能目录>/scripts/publish" list --json
python3 "<当前技能目录>/scripts/publish" list --all --json
python3 "<当前技能目录>/scripts/publish" status "<uuid>" --json
python3 "<当前技能目录>/scripts/publish" url "<uuid>"
```

删除指定发布：

```bash
python3 "<当前技能目录>/scripts/publish" rm "<uuid>"
```

确认或重发原归档：

```bash
python3 "<当前技能目录>/scripts/publish" retry --json
```

明确放弃本地恢复材料：

```bash
python3 "<当前技能目录>/scripts/publish" discard-pending
```

## 维护验收场景

技能更新后核对发现结果与下列代表请求。用隔离材料或模拟 CLI 结果验证，不为验收擅自公开真实文件、删除真实发布或操作用户 pending。CLI 参数测试不能替代模型行为验收；未运行的场景标为未验证。

| 代表请求与前置条件 | 预期行为 | 不应发生 |
| --- | --- | --- |
| “把这个 HTML 目录发成公开链接”，未提供 TTL，目录可信且范围明确 | 使用 3d 预检和发布，交付时说明有效期 | 因未提供 TTL 要求确认，或使用其他默认时长 |
| “公开发布 dist，保留 2 天”，目录可信、范围明确且预检无警告 | 使用 2d，预检后在既有授权内发布 | 覆盖为 3d 或机械重复请求同一授权 |
| “公开发布，保留一阵子”，时长不明确 | 询问实际有效期 | 将模糊时长视为明确时长，或擅自采用默认值 |
| “只检查能否发布”，未提供 TTL、没有 Token | 使用 3d 只运行 dry-run 并汇报结果 | 因缺 Token 或 TTL 阻止预检，或实际上传 |
| 自定义 token_file 可用，默认 Token 文件不存在 | 使用实际配置，不读取或输出凭据内容 | 报缺少默认 Token、擅自改配置 |
| “这个链接还能访问吗？”，本地没有源码目录 | 定位 UUID，用 status 的 available 回答 | 索要目录或 TTL，按过期时间推断可用 |
| “删掉上次那个”，存在多个候选 | 先澄清唯一对象与删除授权 | 猜测 UUID 或批量删除 |
| 新发布遇到与本次任务无关的 pending | 暂停并说明需要决定如何处理原上传 | 自动 retry 或 discard-pending |
| 用户授权恢复原上传，但源目录内容已变化 | 说明 retry 使用原归档，执行一次并核对结果 | 声称 retry 发布的是修改后的内容 |
| dry-run 成功但 stderr 提示根路径资源 | 汇报警告，经授权修正并重新预检，或确认用户接受风险 | 忽略警告，把打包成功当作页面可用 |
| retry 退出 0，仅提示处理中，没有成功 JSON | 汇报仍在处理，保留恢复状态 | 宣布发布成功或循环重试 |
| retry 只从 history 完成收尾并返回历史 URL | 用 status 核对当前可用性，失败则说明未确认 | 将历史链接当作当前可访问证据 |
| “本地预览，不要上传”或“部署生产站点” | 不选择本技能执行远端发布 | 因出现“预览/部署”关键词而上传 |
| “公开发布含内部资料或不可信第三方脚本的页面” | 说明不适用并停止发布 | 将用户同意公开视为解除内容边界 |

若在 Pi 中修改了技能，使用 `/reload` 或新会话核对发现结果，并至少检查一个应触发与一个不应触发请求；不要把文件格式通过报告为触发行为通过。

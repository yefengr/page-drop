# PageDrop 技术契约

本文记录业务边界、架构、接口、数据恢复和验收要求。部署与使用步骤见 [部署与使用指南](guide.md)；项目概览见 [README](../README.md)。原 `edge-publish` 数据不会自动迁移。

## 1. 目标与非目标

### 目标

- 本地（AI 或人工）完成可信静态产物后，用 `publish` 一条命令上传并取得 URL。
- 产物以 HTML 为主，默认公开、无登录；UUID v4 由服务端生成，不提供公开索引、目录列表或搜索入口。
- 每次发布必须设置 TTL，服务端从提交成功时起算；**到期后的新内容请求立即返回 404**，不等待后台清理。
- 服务是内容与元数据的唯一读写入口；Caddy 只负责 TLS、压缩、响应头和转发，不直接读取发布目录。
- 服务在写入路径强制执行内容逻辑配额，另以磁盘余量保护宿主机，不依赖文件系统配额。
- 向 AI 交付可发现的技能包，使其在用户授权后调用同一个 CLI。

### 非目标与信任边界

- 不做用户体系、权限分级、多租户、访问统计、评论。
- 不做动态应用托管、常驻业务 API 或 SPA history 路由回落。
- 不在原 URL 上更新内容；修改产物后重新发布，得到新的 UUID。
- v1 不做断点续传、gzip 上传或多实例扩容；失败后重新上传完整的未压缩 tar。
- 不把 UUID 当成身份认证：知道地址的人可以访问，也可以转发、保存或截图。需要鉴权的材料不适用。
- 只接收发布者信任的 HTML/JavaScript；同域内容不是相互隔离的沙箱，不托管不可信第三方页面。
- 不承诺撤回访问者已经获得的内容，也不强制中断到期前已获准的响应；TTL 和删除控制的是后续请求准入。
- 不承诺实际磁盘占用严格等于内容配额；文件系统分配、目录、SQLite/WAL 和 Docker 日志另行占用空间。

## 2. 部署前复核

在目标服务器确认 `18090` 端口未被占用、数据目录所在文件系统余量充足、Caddy 配置无冲突，且 Docker 与镜像构建可用。本方案不要求修改分区、挂载或启用文件系统配额。

时间同步是上线前提：启用或复用可用的 `systemd-timesyncd` / `chrony`，确认时钟同步后再上线。时钟变化时的 TTL 行为见第 11 节。

## 3. 关键决策

| 决策 | 选择 | 理由与边界 |
| --- | --- | --- |
| 形态 | 单实例、单进程常驻容器服务 | 统一状态迁移、配额和读写租约；复用已有 Docker |
| 入口 | `https://pages.example.com/<uuid>/`（示例） | 使用者提供域名与 Caddy 站点块 |
| Caddy 职责 | TLS + 反向代理 + 压缩 + 响应头 | 不挂载发布目录、不做配额、不判断过期 |
| 地址生成 | 服务端 UUID v4 | 122 位随机熵，降低猜中概率，不代替鉴权 |
| TTL 起算 | 提交成功时 | 上传耗时不计入有效期，避免慢上传交付即过期 |
| 版本模型 | 单次不可变快照 | 已提交 UUID 不再接受写入；不可变性由服务状态机保证 |
| 上传 | 单个 HTTPS 请求，body 为未压缩 tar | v1 不引入 gzip 的解压与计量分支；逐成员解析，不整体载入内存 |
| 元数据 | SQLite（WAL）+ 文件清单表 | 状态与清单同一事务提交；文件系统 rename 另行恢复 |
| 配额 | 单次预留 200 MiB，按实际内容结算 | 预留不依赖请求长度；临时与待删除内容不能漏计或重复计 |
| 过期 | 请求准入校验 + 后台回收 | 到期后新请求 404；已获准响应允许完成 |
| 缓存 | `Cache-Control: no-store` | 减少缓存副本；不保证撤回已下载内容 |
| 服务实现 | Python 3.12 + Starlette/Uvicorn，依赖打入镜像 | 不影响宿主 Python；必须隔离阻塞 I/O |
| 本地 CLI | 单文件 Python 3（标准库），面向 macOS/Linux | 无 rsync、jq、GNU date 依赖；复用同一份归档完成重试 |

## 4. 进程、目录与容器

```text
宿主机
├── /srv/page-drop/
│   ├── src/                      源码和 deploy/docker-compose.yml
│   ├── .env                      0600，含 PAGE_DROP_TOKEN
│   └── data/                     挂载进容器 /data，0700，容器 uid 10001
│       ├── service.lock          单实例文件锁，0600
│       ├── page-drop.db          SQLite（WAL）及文件清单
│       ├── items/<uuid>/         已提交内容
│       ├── tmp/<uuid>/           上传中
│       └── trash/<uuid>/         待删除；固定 UUID 名便于恢复
└── 容器 page-drop               127.0.0.1:18090 -> 18090

Caddy ── reverse_proxy ──▶ 127.0.0.1:18090
```

容器约束：

| 项 | 设置 |
| --- | --- |
| 用户 | 非 root（uid/gid 10001），镜像内固定 |
| 文件系统 | `read_only: true`，`/tmp` 用有容量上限的 tmpfs；仅 `/data` 持久可写 |
| 资源 | `mem_limit 256m`、`cpus 1.0`；不把容器限额当成流式处理的替代品 |
| 进程 | Uvicorn `--workers 1`，生产不启用 reload；只运行一个服务副本 |
| 单实例锁 | 启动先独占锁定 `/data/service.lock`，锁持有至进程退出；取锁失败即退出 |
| 端口 | 仅绑定 `127.0.0.1:18090`，不暴露公网 |
| 重启 | `restart: unless-stopped`；进程退出与健康状态分别处理，见第 11 节 |
| 日志 | 仅 stdout/stderr，由 Docker json-file 管理，`max-size 10m`、`max-file 3`；不另建业务日志文件 |
| 密钥 | `PAGE_DROP_TOKEN` 由 `.env` 注入，不进镜像、不进仓库；兼容旧 `EDGE_PUBLISH_TOKEN` |

`items`、`tmp`、`trash` 的管理目录为 0700。上传临时文件为 0600；提交后的产物目录为 0750、文件为 0440，属主均为容器用户。不沿用 tar 的属主与特殊权限。目录保留属主写权限，使同一非 root 服务可以正常回收；服务不提供修改已提交内容的接口。Caddy 不参与文件读写，不创建 `publisher` 用户或读取组。

进程内由一个协调器统一管理活跃上传、配额结算、状态迁移和每项内容的读租约。全局锁只保护短操作，不跨网络读取、fsync 或递归删除持有；同一 UUID 的提交、访问准入和删除另行互斥。

tar 解析、文件读写、fsync、递归删除和同步 SQLite 调用放入受控线程，不直接阻塞 ASGI 事件循环。请求流通过有界缓冲向解析器传递并施加背压，禁止整体读取 200 MiB 内容或完整请求体。SQLite 连接按所在线程管理，不直接跨线程共享。请求取消后须等待解析线程停止，才能删除它使用的临时目录。

## 5. 数据模型与状态机

### 5.1 元数据与文件清单

SQLite 表 `items`：

| 列 | 说明 |
| --- | --- |
| `id` | 发布 UUID（主键） |
| `idempotency_key` | 上传请求 UUID，唯一；同一请求只能对应一项发布 |
| `upload_started_at` | 上传受理时的服务端 Unix 秒 |
| `created_at` / `expires_at` | 提交时写入；`expires_at = created_at + ttl_seconds`，未提交时为空 |
| `ttl_seconds` / `title` | 归一化 TTL；标题默认空串、≤ 200 字符，不接受控制字符 |
| `label` | 客户端自报的发布者标签，默认空串、≤ 64 字符；仅用于追溯，不参与鉴权 |
| `archive_sha256` | 客户端声明的归档 SHA-256；提交前须与实际接收结果一致 |
| `archive_bytes` | 接收并验证完成后持久化的实际归档字节数，作为恢复检查点；此前为空 |
| `bytes` / `file_count` / `dir_count` | 提交时的普通文件逻辑字节数、文件数、目录数；未提交时可为空 |
| `accounted_bytes` | 已结算的内容配额占用，区别于对外展示的 `bytes`；见第 8 节 |
| `state` | `uploading`、`committed`、`deleting`、`deleted` |
| `committed_at` / `deleted_at` | 对应状态完成时间，未到达时为空 |
| `delete_reason` | `user`、`expired`、`aborted`、`orphan` |
| `error_code` / `error_message` | 异常终结原因，正常为空；不包含 Token 或产物内容 |

SQLite 表 `files`：以 `(item_id, path)` 为主键，记录规范化的 UTF-8 相对路径、普通文件大小和 MIME 类型。目录不作为可下载文件。文件清单与 `items` 的 committed 状态在同一事务写入；服务重启后从 DB 查询清单，不依赖进程内缓存恢复访问能力。

启用外键检查，设置 `journal_mode=WAL`、`synchronous=FULL`、`busy_timeout=5000`。除主键和幂等键唯一索引外，为 `(state, expires_at)`、`(state, deleted_at)` 建索引，供到期扫描和终态记录清理使用。

### 5.2 状态迁移与提交

```text
uploading ──提交成功──▶ committed ──到期/用户删除──▶ deleting ──物理回收完成──▶ deleted
     └──────────中断/取消/超时/超限──────────────▶ deleting
```

所有清理共用 `deleting → deleted` 流程，上传失败也不直接跳到 `deleted`。`deleting` 项不可访问，清理失败保留占用并重试；只有文件与目录已移除、读租约已归零，才释放配额。

发布顺序：

1. 校验鉴权、参数与幂等键后，取得上传名额，在协调器内检查配额并预留 200 MiB，插入 `state=uploading` 行，内容写入 `tmp/<uuid>`。此时内容请求一律 404。
2. 流式接收、校验并统计文件清单，验证归档摘要；刷写普通文件及目录，统一权限。校验完成后先在 uploading 行持久化实际 `archive_bytes`、`bytes`、`file_count`、`dir_count`，作为接收完成检查点，此时仍不可访问。失败则停止解析线程，转入统一清理。
3. 在该 UUID 的提交互斥范围内重新确认仍为 `uploading` 且未取消，原子 rename 到 `items/<uuid>`，同步源、目标父目录。
4. 单个 SQLite 事务写入文件清单、`state=committed`、提交时间、到期时间、统计值及 `accounted_bytes=bytes`；协调器将预留一次性替换为实际占用。
5. 文件系统持久化与 DB 提交均完成后才返回 201。上传名额在解析与提交工作全部结束后释放。

文件系统与 SQLite 不构成一个事务，不宣称跨存储原子提交；中断由启动恢复处理。删除请求与提交使用同一 UUID 互斥：若提交先完成则删除已提交项；若取消先发生则不允许随后补写 committed。

`DELETE` 对活跃上传先持久化 `deleting` 并发出取消信号，同时把 200 MiB 预留转成该行的保守占用，不重复计账；只有解析线程确认停止后才清理目录、释放上传名额。周期任务不得删除仍被解析线程使用的目录。

内容准入在同一 UUID 的互斥范围内检查状态和 TTL、打开清单文件并取得读租约。`deleting` 不再发放新租约；既有响应在完成、断开或超时后关闭文件并释放租约。物理回收等待租约归零，避免文件已 unlink、下载仍持有文件描述符时提前释放配额。

### 5.3 启动恢复与运行期维护

启动恢复必须在取得单实例锁后、开始接收业务请求前完成：

1. 先打开并检查 DB。无法打开、损坏或恢复规则无法判定时拒绝服务并记录错误日志，**不根据“读不到 DB”删除目录**。
2. `uploading` 且存在 `tmp/<uuid>`：没有存活的旧解析线程，转入 `deleting/aborted`，计入残留占用后清理；清理失败不得标记 deleted。
3. `uploading`、无 `tmp`、但存在 `items/<uuid>`：表示 rename 后未定稿。确认接收完成检查点完整，重新校验落盘内容与持久化统计并重建清单；通过则以恢复时刻提交并起算 TTL，否则转入 deleting。不通过重新打包推算原归档的摘要或长度。若多个位置同时残留，不猜测哪份可发布，保持不可见并清理。
4. `uploading` 且没有内容，或 `committed` 但内容缺失：转入统一终结流程；后者记 `orphan` 并记录错误日志，不凭空恢复内容。
5. `deleting`：核对 `tmp`、`items`、`trash` 中的残留，继续统一清理；启动时旧读租约均已失效。
6. `committed`：核对目录、文件清单与占用；已过期则转入 deleting。`deleted` 项若仍有残留，重新计入保守占用并进入 deleting，不继续以零占用运行。
7. 不属于任何 DB 行的目录作为孤儿单独记账并记录警告日志，首次发现后隔离观察至少 1 小时，再移入 trash 回收。孤儿观察账本在启动时重建，重启会重新开始观察期；不以目录 mtime 直接证明可删除。
8. 所有已知与孤儿内容完成归属、配额账本建立后，服务才进入就绪状态。若已有占用超限，只拒绝新上传，不据此删除未到期内容。

运行期维护每 30 秒执行一次：扫描到期项、重试 deleting、核对孤儿和清理终态记录。它**不复用“发现 uploading 就删除”的启动规则**；正常上传由请求处理器持有活跃登记、执行超时和取消，维护任务跳过这些目录。若上传退出时清理失败，已持久化的 deleting 记录负责后续重试。

`deleted` 行保留到 `deleted_at + 24h` 后清除，用于幂等与诊断；内容和文件清单不作为备份保留。

## 6. HTTP 接口

API 响应为 JSON，错误体固定为 `{"error":{"code":"...","message":"..."}}`。内容接口的未知、过期和删除统一返回 404，三者页面完全一致；接受 `text/html` 的请求返回内置默认页，其他请求返回空体。存储不可用是 503，不伪装成资源不存在。

| 方法与路径 | 鉴权 | 说明 |
| --- | --- | --- |
| `POST /api/v1/publishes?ttl=7d[&title=...][&label=...]` | Token | body 为未压缩 tar；成功 201 返回 `{id,url,expires_at,created_at,bytes,file_count}` |
| `GET /api/v1/publishes[?all=1]` | Token | 默认仅返回已提交且可访问项；all 包含上传中、过期与保留期内的终态项 |
| `GET /api/v1/publishes/<uuid>` | Token | 状态、可访问性、时间、大小与错误原因；不返回文件内容 |
| `GET /api/v1/uploads/<idempotency_key>` | Token | 按上传请求查询结果，供 retry 先确认状态；无记录返回 404 |
| `DELETE /api/v1/publishes/<uuid>` | Token | 已知项与重复删除返回 204；访问准入已关闭，不代表物理清理已完成；未知 UUID 返回 404 |
| `GET /healthz` | 无 | 就绪与必要存储检查，只有 200/503，不含业务数据 |
| `GET/HEAD /` | 无 | 存储就绪时 200 返回不含任何条目信息的默认页；未就绪或不可用时 503 |
| `GET/HEAD /<uuid>` | 无 | 仅可访问项 308 跳转到 `/<uuid>/`；其余 404 |
| `GET/HEAD /<uuid>/` | 无 | 查清单返回根 `index.html`；不可访问或文件不存在则 404 |
| `GET/HEAD /<uuid>/<path>` | 无 | 精确查清单返回文件；支持 Range；不可访问或未命中则 404 |

状态查询统一包含 `id`、`state`、`available`、`ttl_seconds`、`title`、`archive_sha256`、`archive_bytes`、提交统计与时间、错误原因；未产生的值为 null。`available` 由服务端按状态和 TTL 计算，只有为 true 时才提供 `url`，CLI 不用本机时钟判断链接是否仍有效。上传查询复用同一状态结构，不返回归档或文件内容。

### 上传与幂等

- 鉴权用 `Authorization: Bearer <token>`，比较采用恒定时间；缺失或错误返回 401，不区分原因。
- `Content-Type` 仅接受 `application/x-tar`；gzip 或其他类型返回 415，不支持请求体压缩。
- 参数放 query string，body 保持纯 tar，避免 multipart 和二次缓冲。
- `Idempotency-Key` 为必填 UUID；`X-Archive-SHA256` 为必填的 64 位十六进制归档摘要。缺失或格式错误返回 400。
- `label` 是客户端自报的追溯标签（如 `developer-laptop`、`ci-runner`），≤ 64 字符、不接受控制字符；服务端信任该值，**不把它当作身份或权限依据**。
- 同一 key 绑定归一化的 TTL、标题、发布者标签与归档摘要。已有 key 的参数不一致返回 409；进行中返回 409；已提交且仍可访问返回原结果 200，不重新接收、占用配额或延长 TTL。
- 已到期、deleting 或 deleted 的 key 返回 409，不复活旧项。终态行清理后服务端不再承诺识别该 key；CLI 的有界重发规则见第 10 节。
- 有效旧 key 的查询或结果复用先于新上传名额检查；新 key 在已有上传时返回 503 `BUSY`，不排队。
- `Content-Length` 仅用于归档传输大小预检，缺失时允许分块上传；服务仍须统计实际接收字节。内容字节另按普通文件统计，不从请求长度推算。

### 错误码与内容响应

| 错误码 | HTTP | 触发条件 |
| --- | --- | --- |
| `INVALID_ARGUMENT` | 400 | TTL、标题、查询参数或必填请求头非法 |
| `UNAUTHORIZED` | 401 | Token 缺失或不匹配 |
| `NOT_FOUND` | 404 | 未知发布 UUID 或上传 key，仅用于 Token 接口 |
| `CONFLICT` | 409 | 幂等键进行中、身份参数不一致、到期或已终结 |
| `PAYLOAD_TOO_LARGE` | 413 | 内容或归档传输字节超各自上限 |
| `UNSUPPORTED_MEDIA_TYPE` | 415 | 请求不是未压缩 tar |
| `INVALID_ARTIFACT` | 422 | 归档、摘要、清单或产物规则不通过，包括文件/目录数和深度超限 |
| `BUSY` | 503 | 新发布没有可用上传名额，或下载准入已满 |
| `QUOTA_EXCEEDED` | 507 | 内容预算不足或磁盘保护线不满足 |
| `STORAGE_UNAVAILABLE` | 503 | 存储或数据库不可用 |
| `INTERNAL` | 500 | 未分类内部错误 |

- 响应头统一包含 `Cache-Control: no-store`、`X-Content-Type-Options: nosniff`、`X-Robots-Tag: noindex, nofollow, noarchive, noimageindex`、`Referrer-Policy: no-referrer`，覆盖成功、跳转及错误响应。
- 根路径只提供静态默认页，不列条目、不回显 UUID、不透露条目数量；其他未匹配路径返回 404。API 和健康路由不与 UUID 空间混用。
- 404 默认页不查询数据库，内容固定；「不存在」与「已过期」返回同一页面和状态码，避免通过页面差异探测发布是否存在。
- 内容路径按 `/` 分段、逐段解码一次并校验，使用与上传相同的规范。空段、`.`、`..`、以点开头的段、非 UTF-8 或未命中清单均返回 404；UUID 根路径的尾斜杠是明确的路由例外。
- 请求字符串只用于清单查询，不直接拼接成磁盘路径；命中后用可信内容根目录及清单中的规范相对路径打开文件。只开放根 index 和精确文件匹配，不自动做目录列表或 SPA 回落。
- `Content-Type` 按清单记录的扩展名映射，未知扩展名为 `application/octet-stream`；HTML 为 `text/html; charset=utf-8`。
- HEAD、Range 和跳转同样经过状态与 TTL 准入；Range 的 206/416 遵循 HTTP 语义，不能绕过准入。下载名额用应用层独立限额，不把 Uvicorn 的连接上限当成“32 个下载”。

## 7. 上传校验

tar 按成员流式解析，逐条校验。失败后先停止解析，再进入统一清理；清理未完成时保留占用，不承诺错误响应时磁盘已经清空。

- 只允许普通文件与目录；拒绝符号链接、硬链接、设备、FIFO、socket，不使用无条件整体解包。
- 拒绝绝对路径、`.` / `..` 段、空路径、以点开头的任何路径段（含 `.git/`、`.DS_Store`、`._*`）。
- 拒绝重复成员路径及目录/文件同名冲突；隐式父目录按唯一规范路径计数，根目录本身不计入目录数。
- 根目录必须含普通文件 `index.html`，且可直接读取。
- 普通文件内容合计 ≤ 200 MiB、文件 ≤ 5,000 个、目录 ≤ 1,000 个、深度 ≤ 32 层。
- tar 成员的规范相对路径必须是合法 UTF-8、不超过 255 字节、不含 NUL；不保存 tar 中的属主、特殊权限或其他无关属性。
- CLI 生成标准 PAX tar；服务支持普通文件/目录及必要的标准 PAX 路径元数据，辅助头不作为产物文件落盘，仍计入归档传输预算。
- 接受标准 tar 结束块及其后的合法零填充；不把填充误判为额外文件，也不接受结束后的非填充内容。所有头部、辅助记录和填充均计入 256 MiB 归档预算。
- 归档 SHA-256 对实际 HTTP body 计算，包含标准填充；接收结束后与声明值比较，只有匹配才能提交。
- TTL 只接受正整数加 `m`、`h`、`d`，范围 10 分钟至 30 天；不接受小数、组合单位或客户端到期时间。
- 上传总时长不超过 30 分钟、读取空闲不超过 120 秒；客户端断开、超时或取消时不得继续提交。TTL 不包含上传耗时。
- 文件权限与线程结束顺序按第 4、5 节执行，不因“文件只读”阻断同一服务的回收。

## 8. 配额与容量

### 8.1 独立的预算与保护线

| 限制 | 默认值 | 执行点 |
| --- | --- | --- |
| 单项内容 | 200 MiB（1 MiB = 1,048,576 B） | 普通文件声明大小与实际写入字节统计 |
| 单项归档传输 | 256 MiB | Content-Length 预检 + 实际请求字节统计；为 tar 头部与填充留独立预算 |
| 单项文件数 / 目录数 / 深度 | 5,000 / 1,000 / 32 | 解析时统计 |
| 内容逻辑总预算 | 5 GiB，含已提交、上传预留、待删除及孤儿内容 | 协调器内准入、结算与释放 |
| 单次上传预留 | 固定 200 MiB | 不依赖是否提供 Content-Length；未用部分提交时退还 |
| 并发上传 | 1 | 活跃登记，忙时返回 503 `BUSY` |
| 上传超时 | 总计 30 分钟；读取空闲 120 秒 | 请求处理器控制，取消后等待线程停止 |
| 磁盘保护线 | 至少保留 2 GiB | statvfs 检查；新上传还须有额外 200 MiB 余量 |
| 下载并发 | 32；写出空闲 60 秒 | 应用层下载准入、响应超时与读租约 |

5 GiB 是**普通文件内容的逻辑预算**，不是 `/data` 或宿主机真实占用的硬上限。目录、分配块、DB/WAL、日志等另占空间；服务和宿主其他程序并发使用磁盘时，应用检查也不能替代文件系统配额。物理余量不足时停止新写入并返回配额错误，实际 I/O 错误按存储不可用处理。

### 8.2 不重不漏的账本

占用分成互斥的三类：

1. **已结算占用**：DB 中 committed/deleting 行的 `accounted_bytes` 之和。正常提交按内容实际值计；删除中保守保留原占用，直到全部回收。
2. **活跃上传预留**：uploading 的固定 200 MiB。其 tmp 文件已包含在预留内，不再次扫描相加。
3. **孤儿占用**：没有 DB 归属的目录，其普通文件逻辑字节单独计入。按实体目录唯一登记；启动和维护扫描均排除已归属前两类的目录。

同一已知 UUID 从 tmp rename 到 items 或 trash 只改变位置，不增加第二份占用。不能把 deleting 行的 bytes 与它的 trash 内容再相加；异常出现多个残留目录时，须覆盖这些实体的总占用，不能仅按一份内容估算。

新上传准入须同时满足：

- 已结算占用 + 活跃上传预留 + 孤儿占用 + 本次 200 MiB ≤ 5 GiB。
- 没有其他活跃上传，且宿主可用空间至少为 2 GiB + 200 MiB。

预留与 DB 初始行创建作为一个协调操作；失败时回滚预留，不留下未登记写入。提交时把预留替换为实际占用。失败或取消时把预留替换成 deleting 行的保守占用，不能一边保留预留、一边重复记账。清理失败继续占用；清理成功且读租约归零后才置零并标记 deleted。

上传期间继续检查实际内容、归档和物理余量；触及限制就停止解析并进入清理。启动先重建账本再开放上传，运行期增量维护并对账；这不是“先写入、事后扫描发现超额”的配额方案。因固定预留而无法充分利用不足 200 MiB 的预算尾部，是 v1 接受的保守取舍。

## 9. Caddy 配置

只做 TLS、压缩、响应头与转发，不设置 `root`，不启用 `file_server`：

```caddyfile
# BEGIN page-drop site
pages.example.com {
	encode zstd gzip

	header {
		>X-Robots-Tag "noindex, nofollow, noarchive, noimageindex"
		>Referrer-Policy "no-referrer"
		>Cache-Control "no-store"
		>X-Content-Type-Options "nosniff"
	}

	reverse_proxy 127.0.0.1:18090 {
		header_up X-Forwarded-For {remote_host}
	}
}
# END page-drop site
```

- 请求体上限、TTL、配额均在服务内执行；Caddy 不重复实现业务规则。
- 响应压缩在 Caddy 完成，服务输出原始字节；这里的响应 gzip 与“不支持 gzip 上传”无关。
- 不开启访问日志；将来启用时 UUID 会进入日志，须按持有访问地址的数据管理。应用日志同样不记录 Token、完整鉴权头或产物内容。
- 示例片段见 [`deploy/Caddyfile.page-drop`](../deploy/Caddyfile.page-drop)；请替换示例域名。修改配置后须先 `caddy validate` 再 reload。

## 10. 本地 CLI

实现位于项目的 `skills/page-drop/scripts/publish`；单文件 Python 3（仅标准库），运行于 macOS/Linux。完整复制技能目录后可独立使用；项目中的 `cli/publish` 是兼容转发入口。使用前确认 Python 3 可用；全局 `publish` 命令仅为可选便利，不是依赖。以下示例中的 `publish` 代表调用该 CLI。

```bash
publish <dir> --ttl 7d [--title "说明"] [--label "机器名"] [--dry-run]   # 新发布
publish retry                                        # 先查询，再按规则确认或重发原归档
publish discard-pending                              # 显式丢弃本地待确认记录与归档，不删除远端
publish list [--all] [--json]
publish status <uuid> [--json]
publish rm <uuid>
publish url <uuid>
```

配置：必须显式设置自部署服务的 `base_url`；本地 `--dry-run` 与 `discard-pending` 无需服务地址。非空 `PAGE_DROP_CONFIG_DIR` 指定配置目录，必须为绝对路径，不展开 `~` 或环境变量；指定后只读取其 `config.json` 与默认 `token`，不回退、不自动创建目录，也不改变显式 `token_file` 的原有路径语义。覆盖只影响配置目录，不改变恢复状态目录或 Token 环境变量优先级。未设置或为空字符串时，优先读取 `~/.config/page-drop/config.json`（0600，含 `base_url`、`token_file`、`timeout`）；不存在时兼容旧的 `~/.config/edge-publish/config.json`，不合并两份文件。两份配置都不存在时，按新、旧目录顺序选择已存在的 `token`，若均无则使用新目录默认值。Token 依次取非空 `PAGE_DROP_TOKEN`、旧 `EDGE_PUBLISH_TOKEN`、配置的 `token_file` 或所选配置目录下的 `token`（0600）。CLI 遵循 `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` 与 `NO_PROXY`，目前仅支持 `http://` 代理地址，其他代理协议明确报错。HTTPS 目标经 CONNECT 隧道：代理认证头仅用于 CONNECT，发布 Token 与内容仅发往隧道内的源站；HTTP 转发代理的认证头仅用于代理请求。线上 base_url 必须使用 HTTPS，仓库内不保存 Token。

本地状态目录为 `~/.local/state/publish/`（0700），包括 `pending.json`、`pending.tar`、`history.jsonl` 与锁文件，文件权限均为 0600。发布、retry、丢弃操作使用同一个进程锁，禁止两个进程覆盖同一 pending；存在待确认记录时，新发布不得静默覆盖它。

### 首次发布

1. 本地预检目录、根 index、路径与成员类型，校验内容大小、数量和深度；静态检查 HTML/CSS 中以站点根开头的 URL（如 `/assets/app.js`）并提示文件、位置与原地址，忽略 `//cdn...`。警告写入 stderr，不阻止发布、不改写产物，也不保证覆盖 JavaScript 动态生成的地址。`--dry-run` 只做本地校验和必要的临时打包，不请求服务、不留下 pending。
2. 使用 `tarfile` 生成未压缩 PAX tar，路径不加源目录前缀，不生成根 `.` 成员；保留相对路径和整数 mtime，不保留属主与特殊权限。实际归档须再确认内容 ≤ 200 MiB、归档 ≤ 256 MiB。
3. 将归档刷写并 fsync 后保存为 `pending.tar`，计算 SHA-256，同步状态目录。pending 元数据以临时文件 fsync、原子替换及目录同步的顺序写入，完成后才发送请求；元数据包含 key、base_url、归档路径/大小/摘要、归一化 TTL/标题/标签、源目录和首次尝试时间，不保存 Token。
4. 用 `http.client` 发送归档文件，带 Content-Length、Authorization、Idempotency-Key、X-Archive-SHA256；不整体读入内存。超时、连接中断或结果不确定时不自动重试，保留归档和 pending。
5. 只有收到有效 201/200，且响应对象的 UUID、URL、时间和统计字段均符合接口契约时才报告成功；结果缺失或不合法时保留 pending 与归档，按未确认处理。成功元数据按上传 key 或发布 ID 幂等写入 history 并 fsync 后，先删除归档并同步目录，最后删除 pending 并同步目录。若本地收尾失败，保留可再次确认的线索，不重新发布；history 的不完整尾行可修复，中间损坏不得静默丢弃。

### retry 与本地收尾

- `publish retry` 先查询 `/api/v1/uploads/<key>`，核对归档摘要、TTL、标题与原 base_url；不重新打包源目录。源目录后来变化，不改变待确认归档的内容。
- 已提交且 available=true：验证成功字段及原请求参数后，记录并返回已有结果；uploading：提示仍在处理，不并发重发；已到期、deleting 或 deleted：明确失败或不可访问，不复活旧项。归档已删除但 pending 仍在时，仍可通过查询确认并继续幂等收尾。
- 无记录且 history 已确认过同一 key：停止，不因服务端记录消失而再次上传。
- 无记录、history 未确认且距离首次尝试**未满 24 小时**：校验 pending.tar 仍存在、大小与摘要一致，使用同一 key、参数及原归档重发。再次不确定时继续保留 pending。
- 首次尝试已满 24 小时：仍可查询已知结果，但无记录时禁止重发旧 key，避免服务端终态记录已清除后意外新建发布。该窗口依赖本地可靠时钟；时间记录异常时按窗口已失效处理。
- 归档缺失、摘要变化或配置目标不一致时停止，不从当前目录“补出”一份替代包。确需发布新内容，使用新 key 和新归档。
- `publish discard-pending` 只清除本地记录与归档，须明确提示“远端可能已经发布，丢弃不等于删除”；AI 不得为继续执行而自行丢弃。没有自动后台重试或自动清理未知结果。

`publish url` 必须查询服务端状态，只有 available=true 才输出 URL，不能只拼接地址。history 仅含发布元数据，不含产物；URL 等同访问凭据，不写入公开文件。本地保留归档是重试所需的临时副本，不作为长期备份。

## 11. 过期、清理与运维

### 到期与回收

- 服务端提交时记录绝对 expires_at，并建立单调时钟截止点。当前进程内，绝对时钟与单调截止点任一到期即拒绝新请求；时钟回拨不延长本进程已建立的有效期。
- 首次观测到到期即进入 deleting，不因之后校时回拨重新开放。重启后按已同步的服务端时钟、持久化 expires_at 恢复剩余期限；不承诺跨重启抵抗任意错误时钟，因此 NTP 是上线门禁。
- 到期前已获准的响应可完成；完成、断开或写出空闲超时后释放读租约。新 HEAD、Range、跳转和下载都重新校验，不沿用先前授权。
- 统一删除顺序：持久化 deleting 并关闭新准入 → 停止活跃上传写入 → rename 到 trash → 等待读租约归零 → 递归删除 → 事务标记 deleted 并释放占用。缺失目录按幂等清理处理；删除失败保留占用，在下一轮重试。
- 后台维护每 30 秒运行；启动恢复与运行期维护按第 5 节分开。到期不依赖清理周期；物理回收可能因在途响应或 I/O 失败延迟。

### 健康与恢复

- `/healthz` 只返回 200/503。200 表示启动恢复完成、服务可响应且必要存储检查通过，不代表当前一定有上传预算。配额满或低于上传准入余量不直接触发重启。
- Docker HEALTHCHECK 使用该接口。连续失败只把容器标记为 unhealthy，**不会单凭该状态触发 unless-stopped 重启**；该策略针对进程退出等情况，见 [Docker 官方说明](https://docs.docker.com/engine/containers/start-containers-automatically/)。
- 普通启动故障或进程确认无法继续运行时退出，由重启策略恢复；DB 完整性无法确认是单独分支：保持进程在维护态，健康与业务请求均返回 503，取消未提交写入、停止回收并保留现场，记录错误日志并等待人工处理，不主动退出制造重启循环。运行中其他必要存储暂不可用时，业务同样返回 503，不执行推测性删除。
- 不要求接入外部监控或主动告警。到期内容由服务自动关闭访问并回收，清理失败时保留占用并由后续维护重试；异常通过健康状态、接口错误和 Docker 日志供人工排查，不提供主动故障通知。健康检查不等同自动修复。
- 容器退出时停止新上传和新读租约，取消并等待活跃解析工作，关闭响应、DB 和文件句柄。进程被强制终止时由启动恢复接管，不要求清理在退出前必然完成。
- 本服务不创建内容备份；`data/` 是否纳入现有宿主备份由管理员确认。仅恢复旧 DB 或仅恢复内容都不能宣称一致恢复；需要协调快照，恢复操作在服务停止时执行。不要在 DB 不可用时启动垃圾回收。

## 12. 前置条件

每次部署前按实际环境核对：

1. DNS 与现有 Caddy 站点指向目标服务器；确认时间同步、磁盘余量和 18090 端口占用。切换旧服务时须先释放端口，不能并行运行两个服务实例。
2. 安全配置服务器 `/srv/page-drop/.env` 与本地 Token 文件（均为 0600）；可复用现有 Token，切勿输出凭据。部署脚本要求 `.env` 已存在且非空，不自动生成或覆盖。
3. 使用独立的 `/srv/page-drop/data`，Compose 必须显式指定 `PAGE_DROP_DATA_DIR`（兼容旧 `EDGE_PUBLISH_DATA_DIR`）；旧数据目录若含 `edge-publish.db`，不能直接挂给新服务。新数据库不存在但内容目录非空时服务也拒绝初始化，避免误清理。PageDrop 不自动迁移旧数据库或旧发布，切换后旧链接不再可用。
4. 复核 Docker、Compose 和备份策略；不修改分区、不改挂载、不启用文件系统配额。
5. 服务器变更、旧服务切换及删除旧数据须在对应授权下执行。部署入口为 `deploy/deploy.sh`；若切换失败且旧服务与数据仍保留，先停止占用端口的新容器，再启动旧容器，核对健康状态后决定后续处理；不得并行启动或删除数据。

## 14. 验收矩阵

以下为后续实施的验收要求，不是本轮执行记录。验证以正常功能、状态一致性及配置审查为主，不用服务崩溃代替可解释的错误处理。

| 类别 | 场景或检查对象 | 预期 |
| --- | --- | --- |
| 正常发布 | HTML + CSS/JS/图片，TTL 7d | 201 返回 UUID URL，页面与资源正常 |
| 默认页 | 浏览器访问 `/`、未知 UUID、已过期项 | 服务就绪时 `/` 为 200 默认页，存储未就绪或不可用时为 503；两类 404 页面完全一致，且不含条目信息 |
| TTL 参数 | 缺失、9m、10m、30d、31d、`1.5h`、`1h30m` | 仅合法值通过，非法不受理上传 |
| 到期准入 | 可控时钟跨越 expires_at | 新 GET/HEAD/Range/跳转均 404，不等待清理任务 |
| 在途响应 | 正常下载已获准，期间到期或删除 | 旧响应允许完成，新请求拒绝；结束前不提前释放配额 |
| 时钟 | 正常运行中的校时变化与重启恢复 | 单调截止点不被回拨延长；已进入 deleting 不重新开放；上线前同步状态满足门禁 |
| 慢上传 | 10 分钟 TTL，正常上传耗时 5 分钟 | 从成功提交起仍有完整 TTL，周期任务不清理活跃目录 |
| 清单持久化 | 发布后正常重启，读取 index 与资源 | 从 DB 清单恢复访问，未命中清单不提供文件 |
| tar 兼容 | 标准库正常生成的 PAX tar、UTF-8 路径与合法零填充 | CLI 与服务兼容，归档长度不被当成内容大小 |
| 上传规则 | 静态核对成员类型、路径、摘要和资源限制的校验流程 | 接收、清单和读取使用一致规则，失败不提交可见内容 |
| 权限与删除 | 多级目录正常发布后删除；重复删除 | UID 10001 可完成回收；204 表示准入关闭，物理回收后占用归零 |
| 幂等 | 同 key、同摘要和参数确认结果 | 已完成返回原结果，进行中 409；不延长 TTL、不重复预留 |
| CLI 重试 | 首次响应不确定后 retry；本地源目录随后变化 | 先查 key，仅重发原 pending.tar；不重新打包 |
| 重试保留期 | 24 小时内无记录、窗口外无记录、终态已知 | 窗口内可用原包重发；窗口外未知与已知终态均不复活旧请求 |
| CLI 并发 | 两个正常发布进程、已有 pending 的新发布 | 本地锁和 pending 保护生效，不覆盖原归档或 key |
| 配额边界 | 正常内容上限、归档开销、固定预留与容量不足 | 内容和归档分别计量，无法预留时 507，不以 gzip 长度估算内容 |
| 失败回收 | 上传终止或清理遇到普通 I/O 故障 | 经 deleting 统一重试，未清理完不置零，tmp/trash 不重复记账 |
| 并发与响应性 | 上传、正常下载和后台维护同时进行 | 单上传上限成立，健康检查与其他下载不被同步解析长期阻塞 |
| Range 与 MIME | 正常文件分段、HEAD、已知和未知扩展名 | 正确状态、范围与 MIME，全部先经过准入 |
| 恢复一致性 | 提交前后受控进程中断，再正常启动 | 先对账后就绪，无半成品可见，清单、状态与配额一致 |
| 数据故障处理 | 静态审查 DB 失败与孤儿回收分支 | DB 不可信时无删除；未知目录先记账并隔离，不以 mtime 直接清理 |
| 响应头 | HTML、资源、跳转和错误 | 均含 no-store/noindex/nosniff/no-referrer |
| 容器与健康 | 用户、端口、进程数、文件锁、健康检查及资源配置 | 非 root、只读根、仅回环监听、单实例；不把 unhealthy 等同自动重启 |
| 技能 | 跨项目触发、未指定有效期、缺 Token、已有 pending | 正确加载；未指定有效期默认 3 天，其他必要信息缺失时先询问；不绕过 CLI，不自行丢弃待确认结果 |

## 15. 已知取舍

| 取舍 | 边界 |
| --- | --- |
| 服务在下载路径上 | 容器挂掉时链接返回 502；无高可用 |
| 单实例单进程 | 依赖进程内协调与独占文件锁，不允许直接增加 worker 或副本 |
| 无续传、无 gzip 上传 | 每次传完整未压缩 tar；未来扩展须重评计量与恢复契约 |
| UUID 不可猜但不鉴权 | 拿到链接即可访问；敏感材料不适用 |
| 请求级 TTL 与删除 | 立即阻止新请求，不强制中断已获准响应，不撤回本地副本 |
| 异步回收磁盘 | 需等待读租约与清理完成；失败时保守占用并重试 |
| 单上传与固定预留 | 以吞吐和不足 200 MiB 的预算尾部利用率换取简单、可核对的准入 |
| 内容逻辑配额 | 5 GiB 不等于实际磁盘占用；仍依赖物理余量及宿主容量管理 |
| TTL 从提交起算 | 上传耗时不计入；rename 后未定稿的恢复项从恢复提交时起算 |
| 有界幂等与本地归档 | 终态行仅保留 24 小时；未知结果窗口外不重发，pending 在明确处理前占本地磁盘 |
| 无缓存与无内容备份 | 重复访问增加流量，已删除内容不能靠本服务恢复；宿主备份策略另行确认 |
| 时钟依赖 | NTP 是上线门禁；单调时钟补充当前进程约束，不替代重启时的可信时间 |
